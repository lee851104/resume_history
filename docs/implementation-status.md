# 實作狀態

## 已完成

- 手機／桌機投遞儀表板、履歷版本上傳下載、手動狀態、追蹤日期及 AI JSON 職缺待辦匯入。
- Google 登入、Supabase RLS 帳號隔離、瀏覽器 AES-256-GCM 加密資料與檔案、私人密碼與離線復原碼。
- Google 信箱復原：可選擇啟用伺服器加密封存主金鑰，驗證綁定 Google 信箱的 OTP 後重新設定私人密碼，沿用同一主金鑰保留資料。未啟用的既有帳號需先解鎖一次。
- 復原 API 檢查已驗證 Google identity、owner header、同來源、OTP user ID／信箱、封存 AAD 完整性；私人密碼不上傳，臨時 OTP session 不寫入瀏覽器。
- 介面不再宣稱管理員無法解密。其他使用者仍受 RLS 隔離；伺服器與復原秘密持有人具備解密能力。
- 15 分鐘閒置保護涵蓋工作台、信箱驗證後的新密碼畫面、啟用畫面與復原碼待確認畫面。帳號切換／登出／重整使先前解鎖操作失效。
- revision CAS、編輯基準比對、遺失回應重試與延遲刷新保護，避免覆蓋其他裝置新資料。

## 驗證範圍

核心測試使用真實 Web Crypto 和 PGlite PostgreSQL；Auth 與 Storage schema 使用 fixture。瀏覽器測試使用模擬登入、密文 API 與 OTP 回應，涵蓋桌面與手機。不能以自動測試代表已驗證真實收信、Google 登入或雲端檔案整合。

信箱復原測試包含：兩種現有憑證匯出主金鑰、連續重設仍保留資料和履歷、錯誤 owner／vault／信箱／秘密／密文拒絕、錯碼與重放不釋出金鑰、未啟用／設定缺漏拒絕、資料庫 RLS、完整介面流程和閒置清除。

## 安全限制

復原不旋轉主金鑰，也不撤銷其他已解鎖裝置；舊封套加舊憑證仍可能解密。伺服器仍可看到帳號、密文大小和存取時間；沒有防伺服器回滾、完整匯出備份或推播。未啟用信箱復原且密碼／復原碼皆遺失時，無法補建解密能力。掌握網站 JavaScript 或使用者裝置的攻擊者不在防護範圍。
