## 已實作

- 電腦／手機儀表板：新增投遞、編輯、搜尋、篩選、進度分布、追蹤清單、履歷版本命名及原檔下載。
- Google OAuth 串接與每帳號 RLS 隔離；無雲端設定時顯示等待連接並停用儲存。
- Google 登入後另外設定／輸入私人密碼；首次產生復原碼，確認另行保存後才建立保險箱。
- 紀錄與檔案名稱先在瀏覽器加密為快照；履歷原始位元組在瀏覽器加密後直接上傳私人 Storage。
- AES-256-GCM、用途／帳號／檔案綁定、PBKDF2 600,000 次迭代；密碼、復原碼、可解密金鑰不送伺服器。
- 以復原碼重設密碼，同時產生新復原碼；管理員不能代為解鎖。
- 手動鎖定、15 分鐘閒置鎖定、重新整理或離開頁面鎖定。跨視窗登出通知及 API 401 清除解鎖狀態；身分變更使舊操作失效。
- 加密 API 驗證 X-Vault-Owner，避免 Google cookie 在操作途中切換帳號造成錯存。
- 多裝置 revision 比對與開啟編輯時的原紀錄比對，避免舊表單靜默覆蓋新資料。
- 舊明文 API 回傳 410；遷移會撤除舊表格／Storage 政策，偵測到舊明文時先中止而非刪除資料。
- 網址不交給伺服器抓取；平台在本機辨識，公司／職缺選填。跨午夜的追蹤日期每分鐘更新。
- 新增 AI JSON 職缺匯入與加密待辦：預覽、勾選、逐筆錯誤、重複網址提示、待評估／準備投遞／暫緩／不考慮、編輯備註，及原子轉換為附履歷的投遞紀錄。固定格式見 docs/ai-job-import.md。
- 舊快照自動補空待辦，無新增資料庫 migration。以請求序號避免延遲的舊刷新回應覆蓋新畫面。

## 安全界線

資料庫與 Storage 管理員取得的是密文；仍可見 Google 帳號、大小、物件數與存取時間。控制網站 JavaScript 的人能惡意修改程式竊取下次解鎖資料，已被控制的裝置也不受此設計保護。

復原不旋轉主金鑰、不撤銷已解鎖裝置；舊封套備份配上舊密碼／復原碼仍可能解密。沒有防伺服器回滾、完整使用者備份匯出或自動推播。密碼與復原碼同時遺失無法救回。
