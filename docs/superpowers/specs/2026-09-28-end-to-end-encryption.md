# 端對端加密改造
使用者已同意 Google 登入＋私人解鎖密碼＋自行保管復原碼，並知悉管理員惡意修改網頁程式仍不在一般網頁能保證的防護範圍。
此規格取代原方案的明文雲端資料與伺服器職缺讀取設計。

## 保護邊界
求職網址、公司、職缺、日期、狀態、備註、履歷檔名及檔案內容在瀏覽器先加密。伺服器、資料庫、Storage 不接收這些明文。Google 身分、隨機物件 ID、密文長度、更新時間與物件數量仍可見。無法防護被控制的裝置、惡意網頁更新、管理員刪除或回放舊密文。

## 密碼與復原
Web Crypto AES-256-GCM，獨立隨機 96-bit IV，AAD 綁定使用者、保險箱 ID、資料用途及檔案 ID。每人一把隨機 256-bit 主金鑰。
至少 12 字元解鎖密碼，PBKDF2-HMAC-SHA256、600,000 次與隨機 128-bit salt 衍生包裝金鑰；雲端只留包裝後的主金鑰。
另產生 256-bit 復原碼，以独立金鑰包裝同一主金鑰。復原碼僅在產生當下顯示／下載到使用者裝置，不上傳。使用復原碼可設定新密碼並產生新復原碼；原密碼/復原碼不再解開目前金鑰封套，但不宣稱已撤銷歷史備份的解密能力。
主金鑰只在頁面記憶體；重新整理、新裝置需解鎖。提供立即鎖定、登出清除、15 分鐘無操作自動鎖定。不保存到 localStorage/sessionStorage。
弱密碼仍可能遭離線猜測；介面提示使用長且獨特的密碼。

## 雲端格式
一個使用者一個 encrypted_vaults row：key_envelope、加密的整份紀錄與履歷索引、revision。修改採 revision 比較更新，衝突回報不覆蓋。第一次建立使用 vault ID 使同一提交重試安全。
檔案放 sealed-resumes 私人 bucket，每個隨機 ID 一份不可覆寫的二進位密文，原檔最多 20,000,000 bytes，加密後最多 20,000,029 bytes。
原始履歷格式在本機檢查，下載密文後在本機解密成原檔。
新增與修改保留原有操作方式；跨帳號 RLS 保留。
搜尋、狀態統計、網址平台辨識在本機完成。取消伺服器職缺內容抓取，顯示連結並允許選填公司/職缺。

## 舊版資料
新增遷移檔，若偵測原明文 tables 或舊 bucket 有資料則停止，不刪除、不自動宣稱已加密。未部署的空白專案可執行兩份遷移。停用全部舊版明文 API，撤銷一般帳號對舊表及 bucket 的存取。已有明文資料者需另做經驗證遷移和備份清理。

## 驗證
真實 Web Crypto 往返、錯密碼/錯帳號/不同用途/竄改拒絕、復原碼解鎖與重設、獨立 IV、密文不含測試明文；整份 payload 與檔案序列化。
PostgreSQL RLS、並行更新衝突、版本不可覆寫、明文遷移 guard。
瀏覽器建立保險箱、確認復原碼、重新整理解鎖、錯密碼、恢復密碼、鎖定清除；網路 payload 不包含測試網址或檔名。
仍須在真實 Supabase/Google/Vercel 設定後驗證跨裝置，不能宣稱本機測試等同外部安全稽核。
